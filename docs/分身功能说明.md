# 分身与轮盘操作

更新：2026-09-30。

## 按键

| 操作 | 行为 |
|---|---|
| 短按 C | 当前位置创建一个分身，立即接管 |
| 长按 C（默认 0.22 秒） | 打开切换轮盘，包含本体及所有分身 |
| 短按 X | 回收最近创建且仍存在的分身 |
| 长按 X | 打开回收轮盘，仅列出分身 |
| 轮盘中移动鼠标 | 高亮对象并预览其摄像机视角，操控对象不变 |
| 松开对应的 C / X | 确认切换 / 回收高亮对象 |
| 鼠标回到中心后松开，或按右键 | 取消操作，恢复原视角 |

回收当前操控的分身时先返回本体，再销毁分身。回收其他分身不会改变当前操控对象。分身编号按创建顺序递增，回收后不会给剩余分身重新编号。

## 等级与持续时间

- 默认 Lv1 / Lv2 / Lv3 最多同时存在 1 / 2 / 3 个分身；本体不占数量。
- AbilityDefinition 的 Echo 各等级 Capacity 可由数据资产覆盖。
- 满额时短按 C 提示先回收，不替换已有分身。
- 降低等级不会自动删除已有分身，但会限制继续创建。
- 分身无计时销毁，本体和分身分别保留位置。未操控的一方继续受重力、碰撞和机关规则影响。
- 单机当前关卡内有效；分身位置暂不写入磁盘存档，重启或换关卡后需重新创建。

## 输入与预览

长按由 PlayerController 统一处理，跨角色接管时不会丢失松键。轮盘打开时屏蔽角色移动、观察和技能输入，但不会暂停整个世界。悬停只更改 ViewTarget，松键才 Possess 或回收；角色各自保留观察方向。中心为取消区域。窗口失焦、暂停、恢复检查点或预览对象失效时取消轮盘。

技能等级在切换时同步；冷却取本体与所有分身的较长剩余值，避免换角色刷新冷却。机关仍通过 bAllowEcho 决定是否接受分身。

## 验证

自动化 Tripothon.Time.PersistentEchoControl 覆盖等级数量限制、原地创建、无寿命、悬停不切换、取消、松键提交、中心取消、回收最新、回收当前后返回本体及拒绝回收无关对象。另使用 lv4 的实际控制器输入链路验证长短按、鼠标预览和 UI 显示。

验证记录：UE 5.7.4 编译通过，15 项 Tripothon 自动化测试通过；lv4 控制器长短按链路的 16 项断言通过（创建数量、预览只切镜头、松键确认、回收及中心取消）。分身胶囊忽略 Camera 通道，避免同位置多个角色挤压镜头。
