# 礼物盒随机奖励

## 测试入口

打开 `/Game/Maps/L_ChaseWhitebox`，出生点两侧有三个礼物盒：

| 盒子 | 位置 | 奖池 |
| --- | --- | --- |
| Gift_Random_AllSkills | (0, -450, 0) | 八项能力等权随机 |
| Gift_StepStone_Upgrade | (0, -900, 0) | 垫脚石，演示配置奖池 |
| Gift_Keepsake_EmptyPool | (0, 650, 0) | 空奖池，演示纪念礼物结算 |

靠近按 **E**，盒盖抬起并显示已领取，HUD 显示获得的技能和等级。礼物区在追逐触发点之前，可以单独测试。南侧礼物区有安全保存范围，可从暂停菜单手动保存。

## 关卡配置

拖入 `/Game/Blueprint/Gift/BP_RandomGift`，它继承原生 `TripoGiftBox`，复用现有 Gift_Box / Gift_Lid 网格。原来的 `BP_Gift` 保留，不会被自动改写。

- **GiftId**：每个盒子在同一地图内须唯一，例如 `Home.Corridor.01`。详情里的 `Generate New Gift Id` 可生成新编号；复制盒子后需要修改编号。相同编号视为同一份奖励，不会重复发放。
- **Rewards**：可配置八项能力和正数权重；权重越大，抽中概率越高。重复能力、非法权重会拒绝领取，不吞掉盒子。
- **InteractionDistance**：默认 240 cm，按角色中心与盒子原点距离检查，同时检查墙体遮挡。
- **OpenSeconds / LidLift**：默认 0.65 秒 / 85 cm，可调整开盖时间与高度。
- **OnGiftOpened**：蓝图事件，携带能力索引和获得等级，可接音效、粒子或额外演出。加载旧的领取状态不重复广播。
- **BoxMesh / LidMesh**：可替换外观和局部变换。盒子主体有碰撞，盖子动画不影响导航。

## 奖励与存档规则

- Buff 指现有八项能力的永久等级：未解锁可升到 Lv.1，同类每次 +1，最高 Lv.3；不增加临时加速、护盾等新 Buff 类型。
- 随机从未满级的有效奖池抽取，使用本轮种子和稳定盒子编号。打开一次只发一份；重复按 E、重复 ID、检查点恢复、分身切换均不能多领。
- 当前操控的本体或分身都可以领取，已存在的分身同步获得同一升级。
- 全部满级或显式空奖池时，盒子仍可打开，记为纪念礼物，技能不变。
- 暂停、恢复中、角色未被玩家操控、待确认挑战奖励时不能开盒。挑战进行中可以拾取，已开始挑战的时间预算快照不重算。
- **领取不会强行覆盖安全存档**。领取记录与技能等级在下一次安全保存时一起写入；读入领取后的存档不会再发奖。若读入领取前的存档，盒子和相应升级都回退，不能叠加刷取。
- 旧 schema-1 存档继续兼容，新增 Gifts 字段缺省为空。新游戏清空本轮领取记录。
- 单机逻辑；Actor 只保存外观状态，领取账本由 GameInstance 的 ProgressSubsystem 持有，跨地图保留。

## 实现与验证

- `World/TripoGiftBox`：距离、遮挡、最近目标、开盖表现与蓝图事件。
- `Progress/TripoGiftRewards`：随机抽取、等级发放与领取账本。
- `TripoProgressPersistence / TripoSaveGame`：账本随安全存档写入、加载和新游戏清空。
- `Player/TripoCharacter`：E 的最近礼物盒交互入口。
- `tools/scripts/setup_gift_whitebox.py`：创建奖励蓝图并装配到白盒，重跑保留已有蓝图和点位。
- `tools/scripts/validate_gift_pie.py`：在新开启的白盒 PIE 中验证按键、奖励、重复领取、遮挡、暂停、分身、满级和恢复；不写用户存档槽。
- `Tripothon.Gift` 自动化测试覆盖保存到内存再读回、旧存档兼容、非法记录、满级过滤和单候选奖池。

## 获取动画与奖励面板

- 开盒成功后弹出透明轮廓信封面板，展示能力图标、名称、等级变化和用途。纪念礼物使用单独文案。
- 盖子上浮、图标缩放亮起、面板淡入使用真实时间播放；展示期间以独立 Reward 暂停原因冻结游戏和技能计时。
- 0.85 秒后可点击“收下礼物 · 继续旅途”，也可用游戏返回键关闭，防止开盒按键误跳过展示。
- 奖励在开盒时仅发放一次，确认按钮只关闭展示。关闭奖励不会解除其他暂停原因。
- 编译通过；19 项自动化测试、27 项白盒检查通过，已实际鼠标点击验证关闭后恢复操作。
