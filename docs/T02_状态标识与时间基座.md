## 实现

`Core/TripoRuntimeSubsystem` 属于 GameInstance，一次会话生成一个 RunId。提供 Blueprint/Python 可用的 `GetRuntime`、`GetActionSeconds`、`SetPauseReason`、`AdvanceRestore`、`GetEpoch` 等接口；没有跨地图 Actor 强引用。

- ActionClock 使用 `FPlatformTime::Seconds` 的差值，查询和暂停边界更新采样，不依赖世界 DeltaTime、时间倍率或日历时间。
- Menu / Loading 是独立、幂等的暂停原因。解除一种原因不会解除另一种；引擎拒绝暂停时回滚原因集合。
- Esc 只切换 Menu。后续读盘/转场代码必须成对设置与解除 Loading；当前同步关卡转场不保留进行中的挑战，Loading 原因仍是可复用接口。
- 日志类别 `LogTripoRuntime` 记录暂停状态、恢复阶段与被拒绝的转换。

恢复顺序：Running → Locked → AbilitiesCleared → WorldRestored → PlayerRestored → HistoryCleared → OverlapsRefreshed → Running。跳步、重复完成阶段会返回 false。HistoryCleared 只增加一次 epoch，供后续系统拒绝旧事件。

**范围说明：**阶段转换只确认调用顺序；真正锁输入、取消技能、恢复机关、清历史与重算重叠由 T03/T04/T05 实施，基座自身不执行这些动作，当前工程由 TripoWorldSubsystem 执行完整事务。普通恢复本身不暂停 ActionClock。

## 稳定身份

`TripoIdentityComponent` 存储实例 GUID 与来源 GameplayTag。当前两个相机区域挂接该组件，并通过 Actor 的 UPROPERTY 持有，确保保存持久化。

- 新实例首次注册生成 ID；普通编辑器复制/导入生成新 ID；PIE 复制保持原 ID。
- World 范围 `TripoIdentityRegistry` 注册弱引用，`Resolve` 以 ID 找 Actor；EndPlay 注销。
- 重复 ID 报错并隔离整个 ID，不随意解析到先注册的 Actor。修复资产后重新加载世界才能解除隔离。
- 原生 Tags：`Tripo.Source.Player`、`Echo`、`MemoryProjection`、`Environment`。这些是来源标识，不自动授予交互权限；权限路由由后续机关系统实现。

已发现并修复：未通过 Actor UPROPERTY 持有的身份组件曾在重载时丢失持久化 ID。现在保存/重载结果逐 GUID 比较通过。Python 必须调用 `Guid.to_string()`，`str(Guid)` 不是 GUID 值。

RunId 目前仅在会话内稳定；存档加载、种子、奖励账本和跨会话恢复仍属于后续任务。动态生成对象的跨会话身份策略也须由生成它的玩法系统提供。
