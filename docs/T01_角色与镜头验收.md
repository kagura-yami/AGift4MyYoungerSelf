# T01 角色与有限镜头

> 本报告记录早期世界锚点实现。后续用户已修正为[角色朝向基准](./角色朝向镜头规则.md)；区域切换角度的历史通过结果不再代表当前镜头行为。

日期：2026-09-15；UE 5.7.4；Windows Development。

## 本次修改

- `TripoPlayerInput` 保留尚未被 Enhanced Input 采样的数字键按下状态，同帧松开在本次输入求值之后交付。长按、映射上下文和动作绑定仍由 Enhanced Input 处理。失焦清键同时清掉待处理事件，避免残留按住状态。
- `TripoPlayerController.KeyForTest` 提供 Development 输入事件测试入口，Shipping 不执行。诊断日志区分按下/松开、处理结果和暂停状态。
- `TripoCameraVolume` 提供范围、锚点角度、优先级。角色使用胶囊已有的重叠列表选区域；同优先级按对象路径确定顺序。离开/销毁区域恢复下一优先级或默认角度。
- Lab 增加两处镜头区域：`(500,-700,150)` 为 90°，`(1700,-700,150)` 为高优先级 −30°。两处均是可移动/可配置的 Actor。

短按处理只保证每次输入采样可看见一次按下，不承诺把同一帧中的多次点击拆成多次游戏动作。普通长按释放不额外延迟；同帧短按的松开最多顺延一次输入求值。

## 根因与对照

修复前：系统空格按下/松开同在日志帧 747，均 `handled=1`，跳跃计数未变。C++ 模拟同帧按下/松开也复现，跨帧按住能跳。由此将问题定位到本机 UE 5.7.4 的输入采样路径，而非系统焦点或键位缺失。

修复后：同帧模拟短按能够起跳；系统短按的 HUD 跳跃计数由 4 增至 5，并观察到胶囊抬升。未采用直接调用跳跃函数来代替这个键盘验收。

## 重跑

```powershell
./tools/scripts/build_game.ps1
./tools/scripts/run_automation.ps1 -Project game/Tripothon.uproject -Test Tripothon.Movement -Report artifacts/verification/movement
```

打开 Lab 并启动全新 PIE 后：

```python
import tripo_input_verify
tripo_input_verify.run('C:/Dev/Projects/UE/Tripothon/artifacts/verification/input-regions.json')
```

此测试在 PIE 副本中移动并销毁优先级区域；重跑要重新启动 PIE。需等待 JSON 的 `ok` 为 `true`，`scheduled` 只代表提交成功。完成后可运行 `tripo_verify.camera_airborne(report_path)`。系统鼠标输入会改变镜头偏移，因此自动回归期间应保持视口无外部输入。
