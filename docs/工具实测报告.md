# 工具实测与最终工作流

日期：2026-09-15。目标：由 Codex 实现全部游戏逻辑，先验证开发工具再开始正式工程；美术制作不在范围内。

## 结论

采用 **UE 5.7.4 C++ + 原生 HTTP MCP + UE Python + Automation/Gauntlet + 独立 Windows 包**。主桥接选 **AvatarGanymede/ue5.7-mcp 0.6.1**。精选四个 UnrealXu Skills 已安装到项目。

已开始正式工程 `game/Tripothon.uproject`，完成最小 Windows Development 包并独立启动。T01 已有可运行操作灰盒，尚未全部验收。全八项能力、机关、成长、存档和剧情仍按原 T00–T21 任务推进，见 [开发进度](./开发进度.md)。

本次测试的是上一版选型中的相关候选及原生工具链，不是互联网上所有工具，也未逐一调用每个插件的数百个接口。判断依据是本项目需要的构建、状态读回、资产保存、输入、截图和失败检测。未验证项明确标出。

## 日常开发闭环

1. 从 [开发进度](./开发进度.md) 选一个依赖已满足的任务，读取对应设计契约。
2. C++ 编写规则和边界测试；可调数据/资源留配置接口。
3. 关闭编辑器后完整编译；避免用 Live Coding 掩盖反射/构造器问题。
4. 打开唯一目标编辑器，health 后核对 `unreal.Paths.project_dir()`。
5. UE Python 装配、编译、保存、重新读取；启动 PIE 后确认真实 Pawn/World。
6. 游戏帧内注入动作，断言真实状态，保存截图和日志；键位/窗口/UI 单独验收。
7. Automation 检查新报告及失败数；阶段交付用 UAT 独立包验证，性能需要时使用 Insights。
8. 同步任务状态、失败原因、可重跑命令和版本。继续下一个任务。

主实现者负责编辑器和构建串行操作。今后若采用多代理，也只分配独立源码/只读审查，地图和蓝图保持单写入者。
