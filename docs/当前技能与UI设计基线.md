# 当前技能与 UI 设计基线

更新：2026-09-29。面向 UI、策划与程序。依据 dibian 分支及本地已合并的二段跳修复核对；该修复尚未提交。本文描述源码默认行为，关卡、蓝图、AbilityDefinition 数据资产可以覆盖参数，最终界面应读取运行时数据。

## 1. 能力清单：7 主动 + 1 被动

下表保留当前 HUD 名称，括号给出更易懂的设计用名。正式改名尚未实施。

| 当前名称 / ID | 操作 | 效果 | UI 必须表达 |
|---|---|---|---|
| 平面位移 / Dash | 左 Shift | 沿移动输入方向冲刺，无输入时沿角色前方；特殊传送点可改变结果 | 冷却、空中次数、特殊入口提示 |
| 上位移（二段跳） / UpDash | 左 Ctrl | 保留水平速度，施加向上初速度，立即受重力影响；地面也能触发 | 冷却与本次空中次数分开显示 |
| 蹬墙跳 / WallJump | 空中按 Space | 面向带 TripoWallJump 标签的墙面时向外、向上弹跳 | 可蹬墙的环境提示、目标无效提示 |
| 垫脚石 / StepStone | 按住 Q 预览，松开 Q 放置 | 在角色脚底相对位置生成限时实体平台 | 虚影、可放性、数量上限、存续时间 |
| 局部减慢 / Slow | F | 减慢前方选中的可受时间影响的移动平台 | 目标标记、减速倍率、剩余时间、冷却 |
| 时回（时间回溯） / Rewind | R 自身；T 平台 | 按历史轨迹回溯自身或符合条件的平台 | 当前回溯对象、进度、历史不足、共享冷却 |
| 分身 / Echo | V 创建，短按 C 顺序切换，长按 C 切换轮盘；短按 X 回收最新，长按 X 回收轮盘 | 原地创建持续分身，悬停预览视角，松键才确认 | 数量、操控对象、轮盘预览与确认提示 |
| 奖励加时 / BonusTime | 被动 | 挑战开始时增加奖励判定的时间预算 | 挑战计时旁的“额外 +N 秒”，无施放键 |

**不要按按键数量算技能数量**：R、T 是同一能力，共享等级、冷却与活动实例。普通跳跃不计入八项能力。传送点是 Dash 的关卡交互，不是第九项技能。

## 2. 默认等级参数

所有能力：0 级锁定，1–3 级可用，3 级满级。下列数值是默认配置，不是最终平衡承诺。距离单位换算：100 cm = 1 m。

| 技能 | 一级 | 二级 | 三级 | 冷却 |
|---|---|---|---|---|
| 平面位移 | 2.42 m | 4.18 m | 7.15 m | 1.4 / 1.2 / 1.0 s；冲刺时间均 0.2 s |
| 上位移 | 基础强度 440 | 660 | 990 | 2 s |
| 蹬墙跳 | 强度 420 | 580 | 750 | 0.2 s |
| 垫脚石 | 存续 8 s，上限 1 | 10 s，上限 2 | 12 s，上限 3 | 2 s |
| 局部减慢 | 原速度 50%，3 s | 原速度 40%，4 s | 原速度 30%，5 s | 8 s；距离 6 m |
| 时回 | 最多回溯 3 s | 最多 5 s | 最多 7 s | 10 s |
| 分身 | 最多 1 个 | 最多 2 个 | 最多 3 个 | 无；分身持续存在 |
| 奖励加时 | +5 s | +10 s | +15 s | 无 |

### 参数展示注意

- 上位移的 440/660/990 是内部基础强度，不是最终起跳速度或跳跃高度。当前公式为 `Vz = sqrt(HeightScale × (Strength² + 2 × g × Duration × Strength))`；HeightScale 默认 0.715，Duration 默认 0.2 s。这里 Duration 用于保留原高度调节含义，**不代表现在仍匀速上冲 0.2 秒**。UI 初版建议展示等级与“再次跃起”，高度预估需要结合实际重力。
- `UpDashHorizontalDistance` 字段仍存在于组件，但当前二段跳路径不读取它。不能把 31.2 cm 当成当前二段跳的保证位移。
- 垫脚石的旧 Distance=200 不决定放置点。默认 StonePlacementOffset=(160,0,16) cm，以脚底为原点、水平视角为方向，不受抬头低头影响。当前不是鼠标任意选点放置。
- 蹬墙跳向外速度为 Strength×0.7，竖直速度为 Strength；探测长度为参数 Reach 60 cm 加代码余量 34 cm。不要将 Reach 标为可跳距离。
- 回溯实际可用时长受已记录历史限制，可能短于等级上限。

## 3. 使用限制与反馈

### 位移能力

- Dash、UpDash 分别记录本次腾空是否使用过；落地重置。冷却结束并不一定意味着空中可以再次使用。
- Ctrl 不清零水平速度，也没有固定速度上冲阶段。不要给它设计“蓄力进度条”。
- 蹬墙跳要求空中、朝向可蹬墙面；同一墙体附近连续蹬跳有限制。普通 Space 起跳与蹬墙跳共用按键。
- 配对传送点要求同 LinkId 恰好两个点，在入口使用 Dash 触发；lv4 的特定入口可配置忽略出口碰撞。成功传送会清零速度并保持视角朝向。详见传送点文档。

### 垫脚石

- 预览与放置共用位置判定。当前线框虚影及 HUD 提示已接入，编辑器还有红/绿调试轮廓；正式 UI 仍需稳定的材质、符号和文字反馈，不能只依赖调试绘制。
- 若关卡存在 BuildAllowed 区域，石块必须完整落入允许区域；没有这类区域时默认允许。禁建区、实体重叠、容量限制仍然有效。
- 放置技能实例立即结束，石块独立存活。不能用 HasActiveAbility(StepStone) 判断石块是否还存在。

### 时间能力

- F、T 当前在角色前方筛选 6 m 内最近的可受时间影响的平台，再做遮挡判定；不是自由鼠标点选，也不是对所有场景物体生效。
- R 不回滚整个世界。自身回溯会抑制角色交互，并清除自身分身；遇到阻挡等情况可能提前结束。
- 回溯至少需要两帧且跨度不小于 0.1 s 的历史。分身不需要历史、不会自动消失，机关通过 bAllowEcho 决定是否接受分身。
- C 再按一次为取消当前分身，不会清除已经开始的冷却。

### 通用规则

成功施放时开始冷却；失败不会新扣冷却。动作暂停时冷却与相关动作计时暂停；恢复存档阶段不允许激活。部分失败当前共用错误码，UI 不应假定程序已经提供更细的原因。

## 4. UI 页面与组件建议（待设计/实现）

### A. 游戏内 HUD

- 技能区：7 个主动技能按“位移 / 造物 / 时间”分组，保留固定位置；每个格子包含图标、按键、等级、冷却遮罩及剩余秒数。时回格子同时标 R/T。
- 位移次数：Dash、UpDash 在冷却之外增加一次性可用标记；耗尽时标“落地恢复”，不能只显示灰色图标。
- 被动加时：靠近挑战时间显示，不占可点击的施放槽。
- 屏幕中央附近：目标平台标记、蹬墙/交互提示；垫脚石虚影留在世界空间。
- 短提示区：展示本次操作失败原因。不要持续遮住角色和落脚点。
- 持续效果区：减速、回溯、分身显示活动状态与进度；垫脚石显示已放数量/上限及各自到期提示。

### B. 技能详情/图鉴

每张详情页包含：名称、当前等级、简短效果、按键、使用条件、当前/下级参数对比。0 级显示锁定，3 级显示满级。图标草案方向：水平箭头、上升弧线、墙面弹跳、石台、慢速时钟、逆时针轨迹、重叠人影、时钟加号。图标仅为美术设计需求，尚未制作。

### C. 奖励与升级

已存在挑战完成后的奖励流程：达标可选候选升级；超时确认固定随机结果；无可升级候选时记录完成；重复练习不重复发奖。UI 应清楚展示当前等级→目标等级、参数变化、选择/确认状态，不能将超时页面做成可自由重抽。

### D. NPC 等级交换

已存在一等级换一等级逻辑。展示扣减来源、增加目标、交换前后等级；保护等级不能扣、满级不能加，相关技能运行中及挑战中不可交换。取消不改变等级。

### E. 调试配置

当前功能 UI 有 F2 能力配置及练习解锁入口。正式玩家界面与开发配置入口需分别设计，避免把直接改等级当作正常成长方式。

## 5. UI 状态矩阵

| 状态 | 视觉/文案建议 | 当前数据依据 |
|---|---|---|
| 锁定 | 锁图标、Lv.0、尚未解锁 | GetLevel=0 |
| 可用 | 清晰图标与按键 | 需要综合使用条件，不能仅判断冷却为零 |
| 冷却 | 遮罩与秒数 | GetCooldownRemaining |
| 执行中 | 活动边框/进度 | HasActiveAbility 与开始/结束事件 |
| 次数耗尽 | 落地恢复 | Movement 的使用次数状态；需 UI 桥接 |
| 无有效目标 | 未找到可作用的平台 | NoTarget；历史技能也可能是历史不足 |
| 放置受阻 | 虚影带禁止符号 | CheckPlacement；需桥接放置结果 |
| 数量已满 | 已达上限，请等待到期 | Capacity |
| 暂停/读档 | 冻结/禁用输入 | Paused / Restoring |
| 被动 | 被动标记，无按键和冷却 | BonusTime |

建议锁定/暂停等禁用状态优先于普通可用显示；活动中与冷却可同时展示。除颜色外增加符号和文字。

## 6. 程序对接边界

**已有 Blueprint 接口**（UTripoAbilityComponent）：GetLevel、GetParameters、GetCooldownRemaining、HasActiveAbility、GetBonusTimeSeconds；事件 OnStarted、OnFailed、OnEnded、OnHit。施放走 TryActivate，不允许 UI 自行修改冷却计时。

**目前不能直接假定已有统一接口**：技能名称/图标/描述本地化表、只读的完整可用性查询、活动效果剩余时间、回溯/分身实际进度、垫脚石列表与剩余寿命、位移剩余次数、升级前后完整参数模型、等级改变通知。上述应在 UI 接入阶段补充只读 ViewModel 或 Blueprint 接口；不能调用 TryActivate 试探按钮是否可用。

当前功能界面由 Lab/TripoSlateHUD.cpp 构建 Slate 文本和按钮，技能名称是静态数组。新界面可沿用玩法组件，视觉重构不应复制一套技能规则。UI 时间取动作时钟，避免另起实时时钟导致暂停后显示不同步。

## 7. 设计验收场景

1. 0/1/2/3 级：锁定、升级、满级都能看懂。
2. 空中使用 Shift/Ctrl 后，冷却完成但未落地，仍明确提示次数限制。
3. Q 按住/释放、位置阻挡、禁建区、达到上限、石块到期都有对应反馈。
4. F/T 无目标、被遮挡；R 历史不足；V 创建、C 切换及对象提示。
5. R/T 显示共享冷却；再次 C 取消后冷却继续。
6. 暂停/恢复/读档后计时与等级同步；奖励和交换后界面立即刷新。
7. 720p/1080p 下技能提示、剧情文本、奖励弹窗不互相遮挡；键鼠按键标签可读。
