# 角色朝向与有限镜头（已被替代）

> 用户再次试玩指出此实现不符合需求。以下内容仅保留历史；当前采用 [GASP 参考与视角主导控制](./GASP参考与视角主导控制.md)。身体带镜头与冻结连续移动基准均已撤销。

2026-09-15，按用户试玩反馈修正。此规则覆盖 v0.2 及早期 T01 报告中的世界相机锚点限制。

- 角色本地 +X 是正前方；CharacterMovement 根据移动方向转动角色。圆润占位体原先已有朝向，只是不易辨认。
- 水平镜头以角色实际朝向为中心，鼠标偏移限制在左右各 35°。角色转向后允许的镜头范围一起转，不受地图坐标或相机区域约束。
- 俯角保持 35°，SpringArm 仍负责墙体遮挡。
- 为避免“角色转向 → 镜头转向 → 输入方向又转向”的循环，连续按住移动时保持这次移动的方向基准；松开后下一次移动采用当前镜头方向。空中不改变输入基准。
- 占位角色前方添加不参与碰撞的锥形标记，尖端沿角色 +X 指向前方，属于调试形体。
- 原 `TripoCameraVolume` 暂保留为稳定 ID 测试载体，其 AnchorYaw/Priority 不再影响角色镜头。后续关卡不得依赖它控制玩家视角。

## 验证

12 项场景检查通过：左右角度限制、跨 180°、旧区域无影响、连续移动不绕圈、松开重取基准、空中跟随朝向且保持输入基准。实际样本：角色 35°、镜头 70°、连续移动基准 35°。

输入/暂停 7 项回归、Automation 5 项均通过。场景测试要求编辑器正常前台帧率，以便在跳跃过程中采样；后台低帧率曾错过短跳观察窗口，不计为通过。

新入口：全新 PIE 中运行 `tripo_facing_verify.run(report_path)`；键位与暂停使用 `tripo_input_verify.run(report_path)`。旧 `tripo_verify.camera_airborne` 转接新镜头测试。早期 T01 的区域角度断言已移除，不再用于当前规则验收。
