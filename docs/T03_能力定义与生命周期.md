# T03 能力定义与生命周期

2026-09-15 的生命周期阶段记录。2026-09-16 已实现八项能力效果，当前运行行为以 [全逻辑实现与验收](./全逻辑实现与验收.md) 为准；以下阶段性测试保留作为基座证据。

## 接入方式

- `ATripoCharacter.Abilities` 持有 `UTripoAbilityComponent`，组件以 UPROPERTY 持有定义和每项能力的 UObject 实例。组件统一推进实例，实例没有自己的 Tick。
- `Definitions` 可配置 `UTripoAbilityDefinition` DataAsset；未覆盖的项使用原生默认定义，运行包无需 Python 生成数据。重复 ID、负值、非有限数、非三档参数会拒绝整个初始化。
- `InitializeDefinitions()` 重复调用不清等级、冷却或活动实例。初始化后更换定义需重新创建组件；不要将它当作热重载 API。
- `GrantLevelFloor(Id, Level)` 仅提升至指定下限，范围 0–3，重复授予不叠加、不降级。`MeetsLevelFloor` 只读，供挑战验证最低配置。奖励加一级的事务在 T06 实现。
- `TryActivate(Id, Target, Handle)` 返回结构化失败原因；先验证等级、目标、暂停、恢复阶段、活动状态、冷却和执行器。只有执行器成功才创建新 GUID、提交冷却并发出开始事件。
- 无目标、未解锁、未实现等失败不产生句柄或冷却。目前没有资源池/消费规则，因此不声称已实现资源扣除或退款系统。
- `Cancel(Handle)` 只取消当前匹配实例；旧句柄、重复取消无效。`CancelAll()` 清理所有活动效果，不退冷却。结束/取消均调用 `EndEffect` 一次。
- `OnStarted / OnFailed / OnHit / OnEnded` 供后续 HUD、音效和表现订阅。命中必须报告当前句柄；旧命中被拒绝。事务回调中递归激活/取消会被拒绝，调用方应在回调返回后处理新的操作。
- `GetBonusTimeSeconds()` 按当前等级返回 0/5/10/15 秒；T06 在挑战起跑时读取并锁定预算。加时始终为被动能力，不能主动施放。

```cpp
Character->Abilities->GrantLevelFloor(ETripoAbility::Dash, 1);
FGuid Handle;
const auto Result = Character->Abilities->TryActivate(ETripoAbility::Dash, nullptr, Handle);
// 默认 Dash 已接入移动执行器；失败时不启动冷却。
```

## 时间、恢复与执行器契约

持续时间和冷却都使用 T02 ActionClock 的绝对时间，不累计引擎 DeltaSeconds。暂停不推进；世界减速不改变冷却速率。等级变化不会重新计算正在运行的效果或已提交冷却。

执行器派生自 `UTripoAbilityInstance`：`Validate` 无副作用；`BeginEffect` 必须原子成功或自行回滚失败，不能在返回失败时留下实体/占用。`UpdateEffect` 收到截至到期时间的 ActionClock 增量，可调用 `RequestCompletion()` 请求本帧正常结束。目标引用、生成实体、占用/减速句柄由具体执行器负责持有和清理。

组件退出时取消全部效果；Tick 发现恢复锁定也会取消。T05 的恢复事务仍须在进入 `AbilitiesCleared` 前同步调用 `CancelAll()`，不能依赖下一帧取消。当前完整恢复事务由 TripoWorldSubsystem 执行，移动由 TripoMovementComponent 仲裁。
